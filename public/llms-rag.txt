# Anvia RAG, Knowledge, and Retrieval

> Current stable v1 context for ingestion, embeddings, vector stores, GraphRAG, and retrieval policy. Updated 2026-11-28; reviewed against Anvia SDK revision `386b66ba`.

Anvia calls its retrieval layer knowledge. Ingest outside the request path; at runtime search a
prepared index and send only relevant, authorized evidence to the model.

```text
source → load → normalize/chunk → embed → index
prompt → permission filter → search/rank → format evidence → model
```

Use static agent context for a small stable source set, automatic vector context when most prompts
need retrieval, a search tool when retrieval is optional or iterative, and portable GraphRAG when
typed relationships add useful evidence. Use application tools for live records and actions. Memory
is conversation history, not a factual corpus.

## Install

```sh
pnpm add @anvia/core @anvia/openai
```

Add one embedding adapter and one durable vector adapter for production. The in-memory store is
appropriate for learning and tests.

Embedding models come from `client.embeddingModel({ modelId })` on `@anvia/openai`, `@anvia/azure`,
`@anvia/gemini`, and `@anvia/mistral`, or from `loadTransformersEmbeddingModel()` in
`@anvia/transformers` for local inference. In the snippets below, `embeddingModel` (an embedding
model) and `model` (a completion model) are application-owned values created this way.

Core does not parse local files. Parse documents or run OCR in application code, then normalize the
result into text documents before chunking or ingestion. Provider adapters may separately accept PDF
attachments for model input; that path does not make Core a file parser.

## Create a vector index

`createVectorIndex()` is the primary handle: it binds a store, an embedding model, and retrieval
defaults once. Omitting `store` uses a process-local `InMemoryVectorStore`.

```ts
import { createVectorIndex } from '@anvia/core/vector-store'

const docsIndex = createVectorIndex({
  model: embeddingModel,
  topK: 4,
  minScore: 0.72,
})

await docsIndex.ingest([
  { id: 'support/reset-links', text: resetLinksDoc, metadata: { published: true } },
])

const results = await docsIndex.retrieve('How long does a reset link last?')
```

The handle exposes `ensure()`/`validate()`, `ingest(input, options?)`, `delete(documentIds)`,
`retrieve(query, options?)`, `asTool({ name })` for an agent's `tools`, and `asContext()` for an
agent's `context`. Options on `createVectorIndex()` are defaults; per-call values win. Pass
`{ store, model }` for a durable adapter or `{ store, models: { dense, sparse } }` for a hybrid
collection. `resetLinksDoc` is application-owned text.

## Ingest documents (lower-level path)

```ts
import { readFile } from 'node:fs/promises'
import type { TextDocument } from '@anvia/core/documents'
import {
  InMemoryVectorStore,
  ingestVectorDocuments,
} from '@anvia/core/vector-store'

const path = 'content/support/reset-links.md'
const text = await readFile(path, 'utf8')
const store = new InMemoryVectorStore<TextDocument>()

await ingestVectorDocuments({
  store,
  documents: [{
    id: path,
    text,
    metadata: { source: path, published: true },
  }],
  embeddingModel,
  chunking: {
    strategy: 'recursive',
    maxSize: 1_600,
    overlap: 200,
    separators: ['\n\n', '\n', '. ', ' '],
  },
})
```

Use stable document IDs so re-ingestion is idempotent; an input without an `id` derives a
content-hash id, which cannot be replaced or deleted by a known id later. The default
`granularity: 'document'` stores one record per source document, keyed by its id. Only
`granularity: 'chunk'` stores one record per chunk, keyed `${documentId}:chunk:${index}`; deleting by
document id on a chunk index needs a store that implements `inspect()`. Preserve source, tenant,
visibility, version, timestamps, and any fields required for authorization or deletion. Validate
remote sources, constrain redirects and response size, reject unsafe content types, and treat fetched
text as untrusted data rather than instructions.

Every bundled vector adapter implements `delete({ documentIds })`, so replacement and removal work
the same way across stores.

## Retrieve automatically

```ts
import { Agent, createVectorContext } from '@anvia/core'
import { vectorFilter } from '@anvia/core/vector-store'

const agent = new Agent({
  id: 'docs-support',
  model,
  instructions: 'Answer from the documentation. Say when the answer is unavailable.',
  context: [
    createVectorContext({
      store,
      model: embeddingModel,
      topK: 4,
      minScore: 0.72,
      filter: vectorFilter.eq('published', true),
    }),
  ],
})

const result = await agent.generate({ prompt: 'How long does a reset link last?' })
```

`docsIndex.asContext()` is the equivalent when you already hold a vector index.

## Metadata filters

`vectorFilter` provides `eq`, `ne`, `gt`, `gte`, `lt`, `lte`, and `in`, plus variadic
`and(...)`/`or(...)` that accept any non-empty list of children. A plain object is shorthand
anywhere a filter is accepted: a bare value means equality and a nested object lists field
operators, for example `{ tenantId, status: { ne: 'archived' }, revision: { gte: 3 } }`.
`vectorFilter.where(shorthand)` and `normalizeVectorFilter()` convert shorthand to the canonical
form. Metadata values must be flat strings, numbers, booleans, or `null`.

The in-memory matcher defines strict type semantics; native adapters translate the operators they
can express and reject unsupported combinations with a descriptive error. `InMemoryVectorStore`
accepts `metric: 'cosine' | 'euclidean' | 'dotProduct'` (cosine by default; higher scores always
rank first). `inspect()` cursors accept only canonical non-negative integer strings.

Build tenant and permission filters from authenticated server state, never model or browser input.

| `@anvia/weaviate` | Native translation | https://docs.anvia.dev/packages/weaviate |
| `@anvia/milvus` | Native translation | https://docs.anvia.dev/packages/milvus |
| `@anvia/chroma` | Native translation | https://docs.anvia.dev/packages/chroma |
| `@anvia/redis` | Native translation | https://docs.anvia.dev/packages/redis |
| `@anvia/lancedb` | Core matcher inside the adapter | https://docs.anvia.dev/packages/lancedb |

LanceDB applies the provider-neutral filter contract inside its `search()`: it fetches nearest
candidates, filters them with the Core matcher, and widens the candidate set until it has `topK`
matches or reaches a bound, so a selective filter can return fewer than `topK` results. There is no
public `filterToLanceExpr` escape hatch. Filtering inside the adapter, before results leave the
store, is still pre-authorization; what to avoid is retrieving broadly into application code and
redacting afterward.

## Search tools

Expose search as a tool when the model should decide whether to retrieve or refine a query. Use
`docsIndex.asTool({ name })` or `createVectorSearchTool({ name, store, model })` from
`@anvia/core/vector-store`; the model's requested `topK` is clamped to the configured value. Keep the
tool read-only, return bounded evidence with stable source IDs, and distinguish retrieved evidence
from provider-generated text. A source establishes provenance, not truth.

Do not allow retrieved documents, web pages, or metadata to invoke privileged tools. Instructions
inside evidence are untrusted content. Apply source policy before indexing and again before showing a
claim to users.

## GraphRAG

Use `@anvia/graph` with `@anvia/neo4j` or `@anvia/memgraph` when schema-first extraction, vector or
hybrid seed search, bounded relationship traversal, and provenance-linked evidence are required.
The portable layer owns schemas (`defineGraphSchema`), raw-text ingestion helpers, retrieval
contracts, Agent tools, and bounded exploration; the adapters own provisioning, persistence, search,
and traversal.

```ts
import { createKnowledgeGraph } from '@anvia/graph'

const incidents = createKnowledgeGraph({ graph, embeddingModel, extractionModel })

await incidents.ingest({ id: 'incident-42', text })

const analyst = new Agent({
  id: 'incident-analyst',
  model,
  instructions: 'Answer from the graph and name the entities you used.',
  tools: [incidents.asTool({ name: 'search_incidents' })],
  context: [incidents.asContext()],
})
```

`graph` is an application-owned registered Neo4j or Memgraph knowledge graph, `extractionModel` a
completion model used for fact extraction, and `text` the source text. Retrieval defaults are
bounded: 8 seed results, depth 2, 40 nodes, 80 relationships, and 12 evidence chunks. Register
resources explicitly, keep hop count and result size bounded, preserve document-scoped writes, and
enforce tenant/visibility predicates before traversal. Do not expose arbitrary Cypher generation as
an authorization boundary.

## Production checklist

- Separate ingestion credentials and workers from request-serving credentials.
- Make upserts, activation, replacement, and deletion idempotent and observable.
- Embed only approved normalized content and preserve provenance through chunking.
- Enforce permissions in the store query; never retrieve broadly into application code and redact afterward.
- Bound top-k, score thresholds, context bytes, query duration, and concurrent embedding work.
- Version embedding model, chunking policy, metadata schema, and corpus snapshots.
- Evaluate retrieval recall separately from answer grounding and faithfulness.
- Log safe source IDs, scores, filters, latency, and index version without leaking document bodies.
